# Releasing Snot for Android

`release-android.sh` builds, signs and publishes a release to a self-hosted
F-Droid repository. Day to day it is one command:

```sh
cp tools/release.env.example tools/release.env   # once, then edit
tools/release-android.sh
```

Run `tools/release-android.sh --help` for the flags that stop it early
(`--no-deploy` to stage a release locally, `--no-publish` to only produce a
signed APK in `dist/`).

## Why the pieces sit where they do

An F-Droid repository is a directory of static files, so the server needs no
code and no secrets — it serves what `fdroid deploy` rsyncs to it. Signing and
index generation happen on a trusted machine.

That split matters because F-Droid pins **two** keys on the client forever: the
repository key that signs the index, and the app key that signs the APK. Losing
or leaking either is unrecoverable — users have to remove and re-add the repo,
or uninstall and reinstall the app. Neither keystore should live on the
internet-facing box, and both want an offline backup.

`tools/signer.sha256`, if present, records the SHA-256 of the release
certificate; the script refuses to publish an APK signed by anything else.
Create it after the first release, once you are sure the key is the right one.

## One-time: the server

Any static web root will do. On an Arch-family host:

```sh
sudo useradd -r -m -d /srv/fdroid -s /bin/bash fdroid
sudo install -d -o fdroid -g fdroid /srv/fdroid/fdroid
sudo pacman -S nginx-mainline certbot certbot-nginx
```

Add the publishing machine's SSH public key to `/srv/fdroid/.ssh/authorized_keys`,
point an nginx `server` block with `root /srv/fdroid;` and `autoindex off;` at
the hostname, and get a certificate with `certbot --nginx`. TLS is not what
makes the repo trustworthy — signatures do that — but it keeps the client's
cleartext-traffic policy happy and stops middleboxes rewriting downloads.

## One-time: the repository

```sh
pipx install fdroidserver
mkdir -p ~/snot-fdroid && cd ~/snot-fdroid
fdroid init --distinguished-name "CN=f.snot.app, OU=F-Droid"
```

`fdroid init` writes `config.yml` and the repository keystore, and prints the
fingerprint users need. Then set in `config.yml`:

```yaml
repo_url: "https://f.snot.app/fdroid/repo"
repo_name: "Snot"
repo_description: "Official builds of Snot, an open source notes app."
archive_older: 3
archive_url: "https://f.snot.app/fdroid/archive"
serverwebroot: "fdroid@f.snot.app:/srv/fdroid/fdroid/"
```

The first `tools/release-android.sh` run stubs out
`metadata/app.snot.notes.yml`; fill in `License: GPL-3.0-or-later`, `Summary`,
`Description` and the source/issue URLs, drop an icon and screenshots under
`repo/app.snot.notes/en-US/`, and run the script again.

Users then add:

```
https://f.snot.app/fdroid/repo?fingerprint=<the fingerprint fdroid init printed>
```

## Why a universal APK

`--split-per-abi` is deliberately not used. Tauri's generated
`gen/android/app/build.gradle.kts` gives every ABI the same `versionCode`, and
F-Droid rejects two APKs of one package that share one. Since `gen/` is
regenerated by `cargo tauri android init` and not tracked, an ABI-offset patch
to that Gradle file would not survive; the universal APK is bigger but correct.

For the same reason the release APK is signed out-of-band with `apksigner`
rather than by a Gradle `signingConfig`.
